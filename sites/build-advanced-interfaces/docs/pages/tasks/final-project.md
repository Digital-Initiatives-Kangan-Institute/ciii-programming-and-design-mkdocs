# Final Project

## Plan Your Project

!!! abstract "Instructions"
    Create a project proposal for your final web application. This is the planning phase — no code yet.

    Your proposal must include:

    - A description of what the project will do and who it is for
    - A feature list outlining what the user can do
    - A wireframe (hand-drawn or digital) showing the main pages and layout
    - A backlog or checklist of tasks to complete

    Prepare any assets, content, data sources, or API needs for the build phase.

    Push your proposal to GitHub.

??? hint "Hint - Click to expand"
    Start by defining the user need: what problem does your app solve? Then list features in order of priority (must-have vs nice-to-have). Your wireframe does not need to be polished — a sketch showing where the navigation, content, and key elements go on each page is enough. The backlog should be a simple checklist of build tasks.

---

## Build and Present

!!! abstract "Instructions"
    Build your final web application based on your proposal. This is the culmination of everything you have learned.

    Your final project must:

    - Use Next.js with TypeScript
    - Include multiple pages with routing
    - Fetch and display data from an API or Supabase
    - Use components (either custom, Mantine, or both)
    - Have a polished, consistent user interface
    - Be deployed to a live URL

    Prepare a demo or progress review showing the core features working. Push your project to GitHub with the deployment link, screenshots, and a reflection.

??? hint "Hint - Click to expand"
    Break your build into small, achievable steps from your backlog. Start with the project setup and layout, then add routing, then data fetching, then polish. Test each feature as you build it. Your reflection should cover: what went well, what challenges you faced, and what you would do differently next time. Screenshots should show the key pages and features working.
